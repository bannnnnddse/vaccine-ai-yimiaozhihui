# 细胞 IP 图解：Wan 2.7 Image Pro 与 Qwen 3.7 Flash 适配说明

本目录承载“细胞 IP 科普图解”在项目图像生成链路中的素材、提示词规范与运行时契约。当前生产链路采用双模型分工：**Qwen 3.7 Flash** 将用户的自然语言需求改写为结构化、可校验的中文图像 brief；**Wan 2.7 Image Pro** 根据该 brief、受控参考图与程序编译的最终提示词生成或局部编辑图片。

这套适配的重点不是让模型自由发挥，而是将“科学关系、固定角色身份、版式规则、中文可读性”拆开治理。Qwen 负责理解与压缩需求，Wan 负责视觉生成，应用程序负责锁定不可变约束并验证输出。这样可以避免直接把一段模糊需求交给图像模型时常见的角色漂移、箭头错误、信息过密和科学关系被补写等问题。

## 总体流程

```text
用户原始中文需求
        │
        ▼
Qwen 3.7 Flash：路由 + 提示词改写 + JSON 结构化
        │  ChineseFigureBrief
        ▼
应用程序：profile 判定、角色别名匹配、参考图选择、约束编译
        │  最终 Wan 提示词 + 0–2 张受控参考图
        ▼
Wan 2.7 Image Pro：异步生成 / 局部编辑
        │
        ▼
PNG 校验、视觉审查、版本化保存与人工确认
```

其中，`backend/app/services/science_image_organizer.py` 实现 Qwen 侧的改写与路由；`backend/app/services/wan_image_generator.py` 将 brief 编译为 Wan 提示词；`backend/app/services/wan_api_client.py` 负责 Wan 的提交、轮询、下载与重试；本目录中的 `runtime-profile.json` 和 `assets/manifest.json` 则提供角色与参考图的机器可读配置。

## Wan 2.7 Image Pro 适配

### 统一生成模型与调用方式

图像服务默认配置为 `wan2.7-image-pro`，由 `DASHSCOPE_IMAGE_MODEL` 控制；局部编辑使用同一 Wan 2.7 系列模型。应用不依赖旧图像生成 SDK，而是通过自有 HTTP 客户端调用 DashScope 的异步图像生成接口：

1. 将文字提示词与参考图放入同一条 user message；
2. 提交异步任务，携带单图生成、关闭水印和配置化尺寸参数；
3. 按任务状态轮询，直到成功、失败、取消或超时；
4. 下载生成结果，确认响应是图片并校验为可解码 PNG；
5. 将通过校验的版本写入受控的生成目录。

网络请求与图片下载均针对临时网络错误、429 和服务端错误进行有限重试；鉴权失败、无效任务状态、非图片下载响应和超时会被明确识别，不会把异常响应当成图片交付。

### 参考图输入的适配

Wan 接收参考图时，应用会先以 Pillow 验证其为 PNG、JPEG 或 WEBP，再将其编码为 `data:<mime>;base64,...` 形式传入请求。该过程避免了本地路径、损坏文件或不支持的格式直接进入模型请求。

细胞 IP 场景的参考图选择遵循严格的两张上限：

| 命中情况 | 发送给 Wan 的参考图 | 编译进提示词的约束 |
| --- | --- | --- |
| 命中 1–2 个固定角色 | 每个角色各发送一张独立 canonical 图 | 每张图只用于对应角色的颜色、轮廓、面部和专属道具 |
| 命中 3 个及以上固定角色 | 发送一张完整角色总表 | 明确点名允许从总表提取的角色，并要求忽略其余角色 |
| 未命中固定角色 | 发送角色总表作为整体扁平手绘语言参考 | 明确禁止复制总表中的任何具体角色或专属道具 |
| 常规科学图解 | 根据图像类型发送唯一运行时风格参考 | 仅参考总体视觉语言，不复制文字、数据、Logo 或具体主体 |

参考图永远不是“照抄图片内容”的指令。最终提示词会逐图声明其用途，并明确禁止复制原图的文字、事件与构图。固定角色的身份信息由 canonical 图和 `assets/manifest.json` 共同控制，场景描述无权重新设计角色外形。

### 画幅、文字与信息密度

Wan 的生成尺寸来自运行时 `WAN_IMAGE_SIZE` 配置；画幅表达则在最终提示词中由 profile 明确约束：

- 普通 `scientific_diagram`：9:16 竖版，自上而下阅读，保留一个简短中文标题；
- `cell_ip_editorial`：16:9 横版单场景，最多两个核心关系，不使用标题；
- `cell_ip_scientific`：16:9 横版科学图解，允许标题、编号、箭头和分区，最多四步因果链。

为了避免 Wan 将复杂主题压缩成只有几个角色的静态画面，程序会根据 causal steps 派生“视觉复杂度契约”。该契约规定至少应有的信息分区、可辨识节点、方向连接、标签步骤，以及是否必须使用编号和标题。它只允许复用同一因果链中的起点、过程、结果和状态变化，**不允许**为凑信息密度新增科学实体、数据或结论。

### 生成与编辑的连续性

生成结果通过 PNG 校验后才会成为可展示版本。若进入局部修改流程，Wan 接收原始成图、文本修改要求、标准化选区及同一组 IP 参考图；选区先换算为像素坐标，随后以 `bbox_list` 执行编辑。这样可以把“修改某个标签”“修正箭头方向”等操作限制在指定区域，同时沿用第一次生成时已经确定的角色身份与参考图。

## Qwen 3.7 Flash 提示词改写适配

### 为什么不直接把用户输入传给 Wan

用户输入往往同时混有主题、风格偏好、科学描述、角色要求和不完整的视觉想法。例如“画一张疫苗如何起作用的可爱细胞图”并没有说明核心因果链、所需角色、箭头顺序、中文标签或是否应该使用正文插画。直接生成会导致图像模型自行补全机制，或者在“可爱”与“严谨”之间失去一致性。

因此，系统先用 Qwen 3.7 Flash 把原始中文需求收束成一个受 Pydantic 校验的 `ChineseFigureBrief`。Qwen 调用使用 JSON object 响应格式并关闭 thinking，使输出稳定地进入下游编译器，而非直接产生一段难以解析的说明文字。

### 结构化改写输出

Qwen 必须输出且只能输出以下字段：

| 字段 | 作用 |
| --- | --- |
| `image_type` | 在 `science_poster`、`graphical_abstract`、`mechanism_diagram` 中选择图像类型 |
| `generation_route` | 固定为 `fast`，保证进入 Wan 图像链路 |
| `visual_profile` | 初步表达普通科学图解、正文 IP 插画或 IP 科学图解的适配方向 |
| `scene_direction` | 仅描述动作、位置、朝向、交互和构图关系 |
| `optimized_chinese_prompt` | 已压缩、可执行的中文图像主体提示词 |
| `chinese_labels` | 1–8 个简短中文标签候选 |
| `scientific_claims` | 1–8 条简洁科学表述 |
| `core_causal_steps` | 按顺序排列的 1–4 条不可再分科学关系 |
| `route_reason` | 简短说明 profile 和图像类型选择原因 |

该 schema 对额外字段、空值和数量范围进行限制。对于模型偶发的旧格式或轻微 JSON 形状漂移，应用会做最小的兼容归一化：将字符串步骤转换为 `primary_relation` 对象，必要时以已有科学表述补足步骤，并将历史 route 统一到 `fast`。不符合 schema 的结果不会直接交给 Wan。

### Qwen 的改写规则

Qwen 的系统提示词将原始需求改写为“可被图像验证”的指令，而不是复述用户句子。改写时重点执行以下规则：

1. 先识别图像类型与阅读任务，再选择合适的视觉 profile。
2. 把机制拆成最多四条、顺序明确的核心关系；每条关系都要能被箭头、位置变化或状态变化呈现。
3. 以简体中文生成可读标题/标签，并限制标签数量，避免把段落文字塞进图片。
4. 保留输入明确支持的科学内容，不编造精确数值、百分比、日期、分子连接、疗效保证或个体化医疗建议。
5. 只列出科学关系真正需要的角色；角色资产的存在不能成为新增实体或机制的理由。
6. 当用户已点名固定角色时，Qwen 只可描述它们的语义动作、位置、方向、比例和交互，不可重写颜色、轮廓、服饰、道具、面部或其他身份特征。

例如，原始需求“画疫苗接种后如何建立免疫记忆，带细胞 IP”会被改写为按因果顺序排列的实体与关系，而不是泛化成“几个可爱的细胞一起保护身体”。固定角色由后续资产服务锁定，Qwen 不拥有角色外观的决定权。

### profile 的确定性纠偏

Qwen 会给出初步 `visual_profile`，但最终选择由应用根据用户原始需求、核心步骤数和主题词进行确定性纠偏：

- 没有启用细胞 IP，或主题并不涉及细胞、病毒、抗原、抗体等细胞性对象时，统一使用 `scientific_diagram`；
- 用户明确要求固定 IP/手绘角色/正文配图，且不超过两步、未要求流程或严谨机制时，使用 `cell_ip_editorial`；
- 细胞、病毒、抗原或抗体相关主题默认使用 `cell_ip_scientific`；明确要求机制图、流程图、图形摘要、箭头、分区或三个以上关系时也使用该模式。

这一层纠偏防止模型把复杂机制误判成轻量正文插画，也防止没有 IP 诉求的普通图解被强制角色化。

### 角色锁定与二次匹配

角色匹配不会只依赖用户的原始用词。系统先在原始需求中按 `assets/manifest.json` 的角色名称与别名匹配，再从 Qwen 已校验的标签、科学表述和 causal steps 中再次匹配，最后按首次出现顺序合并去重。

二次匹配解决了“用户只写水痘疫苗机制图，而改写后出现树突状细胞、辅助性 T 细胞、记忆 B 细胞”等情况。与此同时，锁定角色列表由应用写入 brief，而不是让 Qwen 自行声明。后续若 `scene_direction` 出现“某锁定角色是红色、戴帽子”等重新设计身份的自由外观文本，程序会丢弃该段场景描述，回退到已校验的核心关系，避免提示词污染角色契约。

## 最终 Wan 提示词如何编译

Qwen 输出不是最终发给 Wan 的文本。应用会将 brief 编译成两个模板之一：

| 场景 | 最终模板 | 关键内容 |
| --- | --- | --- |
| 普通科学图解 | `FAST_WAN_PROMPT_CONSTRAINTS` | 9:16 画布、中文文字限制、核心关系、标签、阅读路径和复杂度契约 |
| 细胞 IP 图解 | `CELL_IP_PROMPT_CONSTRAINTS` | profile 画幅、角色身份契约、逐图参考用途、角色总表筛选、科学边界、禁忌和复杂度契约 |

两类模板都把 `core_causal_steps` 编号编入“科学边界”，明确要求所有箭头方向与关系一致，并禁止补充未给出的角色、机制、精确数值或治疗承诺。用户原始需求会附在最终提示词末尾，作为表达重点的补充，但其优先级低于已校验的科学关系、角色锁定和版式契约。

对于细胞 IP 图解，编译器还会从 `runtime-profile.json` 注入：

- `aspect_ratio`、最大因果步骤数和是否允许标题；
- 单场景或因果图解的构图指令；
- 适用的手绘/科学视觉语言；
- 禁止项，例如 3D、错误箭头、密集长文字、无关角色和疗效保证；
- 每张参考图的用途，以及从角色总表中可选和不可选的角色。

这使得 Wan 接收到的是一份分层且可追溯的生成说明：上层是科学事实和因果链，中层是画幅、阅读路径与文本预算，下层才是角色和风格。任何一层都不能覆盖上层约束。

## 素材与运行时配置

| 文件 | 在适配中的职责 |
| --- | --- |
| `runtime-profile.json` | profile 的画幅、步骤上限、参考图上限、构图、标题策略与禁忌；是唯一机器契约 |
| `assets/manifest.json` | 角色 ID、别名、外观描述和 canonical 资产路径；用于确定性角色匹配 |
| `assets/flat-characters/` | 少量命中角色时发送给 Wan 的独立身份参考 |
| `assets/flat-character-sheet.png` | 多角色选择或无固定角色时的总表参考 |
| `references/character-bible.md` | 供人工审阅角色身份与组合逻辑 |
| `references/style-dna.md` | 供人工审阅手绘视觉语言与禁忌 |
| `references/qa-checklist.md` | 成图后检查角色、箭头、标签、科学关系和版式的依据 |

修改角色、别名、资产路径、参考图预算或 profile 能力边界时，必须同时维护相应 JSON、素材与后端测试。仅修改 Markdown 文档不会改变实际生成行为。

## 可追溯性与验收重点

每个图像任务会保存原始用户需求、结构化 brief、最终编译提示词、使用的图像模型、profile、锁定角色、计划使用的参考资产、实际发送的参考图名称、复杂度契约、版本信息和审查结果。这样可以回溯“某张图为什么用了这些角色、为何采用这一画幅、箭头和标签来自哪条因果关系”。

验收时优先检查以下问题：

- Qwen 是否把原始主题拆成了完整且没有越界的 causal steps；
- 最终 profile 是否与内容复杂度相符；
- Wan 是否只使用了被锁定的角色，而没有从参考总表额外复制角色；
- 箭头、编号、分区和标签是否仍忠实表达每条核心关系；
- 图中文字是否为简短、可读的简体中文，且没有乱码、密集段落或无依据数值；
- 成图是否通过 PNG 校验和视觉审查，局部编辑是否保持了非目标区域和角色身份的一致性。

通过上述分工与约束编译，Wan 2.7 Image Pro 的视觉能力能够被用于稳定生成，而 Qwen 3.7 Flash 的中文理解能力则被用于把模糊需求改写成可执行、可验证且适合科学传播的图像提示词。
