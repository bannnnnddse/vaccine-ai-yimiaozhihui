# 正文插画构图与微型叙事

本文件只适用于 `cell_ip_editorial`；科学机制图请使用 `scientific-prompt-template.md`。

每张图先确定一个可在 3 秒内读到的因果：**触发 → 行动 → 结果**。把故事压缩在一个横版场景里，而不是画成分镜、流程图或单纯的角色排列。主角应占据最清楚的动作位；触发物或阻力放在它的视线、路径或前方；结果以道具状态、位置变化、被保护/被拦住的对象或环境变化呈现。

| 文章结构 | 推荐故事关系 |
| --- | --- |
| 一个判断 | 主角发现一个信号、裂口或边界，并正做出对应选择；结果已经露出端倪 |
| 传递 | 一个角色带着有时效的信号赶到交接点，另一角色伸手承接，信号继续向目标移动 |
| 对抗 | 威胁正逼近一个明确目标；防御角色在关键位置拦截、包围或封住入口 |
| 流程 | 3–5 个角色沿一条有方向和节奏的路径接力；每一棒改变对象状态，不画编号步骤 |
| 前后对比 | 同一角色因一次触发从左侧的受阻/未激活，转向右侧的行动/完成状态，用中间痕迹连接 |
| 系统协作 | 一个共同目标处于风险中；每个角色做不同且可见的动作，形成“有人发现、有人传递、有人处理”的闭环 |
| 常见坑/纠偏 | 主角先被错误信号、拥堵或伪装阻住，随后借助线索、同伴或工具改正路线 |
| 记忆与待命 | 风暴已过去，主角保留关键标记守在入口或地图旁；远处只留微弱风险，强调准备而非静止 |

用前景放触发物或迫近威胁，中景放主角的关键动作，远景只放必要的目标或结果。可使用脚步、箭头式运动线、散落线索、半开的门、光点余迹等轻量环境线索制造时间感；不要堆砌道具或另起支线。改变主角、方向、道具、重心和留白，避免反复使用相同队列或环形结构。
