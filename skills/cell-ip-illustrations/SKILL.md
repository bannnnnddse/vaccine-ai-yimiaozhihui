# 细胞 IP 正文配图

为中文文章或科学解释图使用固定细胞角色 IP。先判断任务属于正文插画还是科学图解；IP 只约束角色身份和相容的视觉语言，不能删减用户要求的科学关系。

应用运行时以 `runtime-profile.json` 为唯一机器契约。修改 profile、参考图策略或能力边界时必须同步更新该文件和后端测试，不能只修改 Markdown 提示。

## 模式选择

- `cell_ip_editorial`：文章正文配图、单一判断或不超过两个关系。使用“触发 → 行动 → 结果”的单场景表达，可无标题并保持较多留白。
- `cell_ip_scientific`：机制图、图形摘要、三至四步因果链、明确要求箭头/流程/严谨科研表达。完整保留每一步，允许标题、编号、箭头和分区。
- 普通科学图解没有明确要求固定 IP 时，不启用本 skill，由应用的 `scientific_diagram` profile 处理。

遇到“IP 风格”和“严谨机制”同时出现时选择 `cell_ip_scientific`；不得套用正文插画的单场景禁令。

## 先读这些参考

- `references/character-bible.md`：固定角色 IP、颜色、外形和道具。每次必读。
- `references/style-dna.md`：视觉层、色彩、文字与禁忌。每次必读。
- `references/composition-patterns.md`：正文插画的结构类型、视觉隐喻和避免重复构图。选择 `cell_ip_editorial` 时读。
- `references/prompt-template.md`：正文插画提示词模板。选择 `cell_ip_editorial` 时读。
- `references/scientific-prompt-template.md`：科学图解提示词模板。选择 `cell_ip_scientific` 时读。
- `references/qa-checklist.md`：生成后的检查与迭代规则。生成后必读。
- `assets/flat-character-sheet.png` 与 `assets/flat-characters/`：角色视觉校准；生成时作为参考图使用。
- `assets/manifest.json`：应用运行时使用的机器可读角色清单；角色名称、别名、造型或文件变化时必须同步更新。

## 参考图策略

- 命中固定角色的实体，优先使用 `assets/flat-characters/` 下对应的独立角色资产（每个锁定角色一张 canonical 参考）。
- 参考图预算有限（当前为 2 张）：当需要 3 个及以上固定角色时，改为把 `assets/flat-character-sheet.png`（完整角色总表）作为单张参考图，并通过提示词明确告诉模型“从总表中提取哪些角色、保持哪些造型、忽略哪些角色”。
- 未收录细胞没有独立资产，不再使用单独画风锚点；它们沿用与总表一致的整体扁平手绘画风（由运行时 profile 的 style 指令约束），但不得使用任何固定角色的专属颜色、轮廓或道具。

## 工作流

### 1. 消化正文

先读用户给的正文、链接、Notion 页面、Markdown 文件或截图内容，提炼：核心观点、认知转折、适合用图解释的段落，以及只适合文字的部分。

不要平均配图。优先选择认知锚点：核心判断、输入输出闭环、分流、前后对比、承接路径、常见坑或角色状态变化。

为每张候选图补全一个最小叙事单元：谁在什么情境下想完成什么、什么信号或障碍迫使其行动、发生了什么关键动作、读者最后能看到什么结果。叙事只承载文章判断，不为热闹额外增加支线、笑料或无关角色。

### 2. 先出配图策略

当用户只要求分析如何配图时，先给 shot list。每张图写清楚：

- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- 核心细胞角色及动作
- 触发事件、阻力或转折，以及结局画面
- 建议元素
- 建议中文标注词

默认 4–8 张；短文 1–3 张；长文通常不超过 9 张。

### 3. 单张生成

当用户明确要求生成、输出或做图时，使用 `image_gen` 每张单独生成，不拼接多张成品。正文插画只讲一个核心结构；科学图解可在一张图中完整呈现最多四步受支持的因果链。

生成前只选择正文或科学关系明确需要的角色。没有命中固定角色时，可以使用完整角色总表仅作为整体画风参考（`role-sheet:style`），并生成不带既有角色专属颜色、轮廓或道具的相容细胞；绝不把总表当作“默认角色”复制进画面。正文插画默认 1 名主角；科学图解可按因果步骤使用必要角色。角色的颜色、轮廓和专属道具必须固定。

正文插画先确定故事弧：触发（信号、威胁、缺口或任务）→ 行动（追踪、交接、守护、求援或纠偏）→ 结果（被拦截、被送达、被激活、被守住或进入待命）。科学图解改为逐条映射实体、关系、箭头方向和结果，不强求单场景故事弧。

正文插画按 `cell_ip_editorial` 契约生成。科学图解按 `cell_ip_scientific` 契约生成，允许流程、箭头、编号和必要标题；风格要求不得覆盖科学结构。

每次根据当前文章重新选择简洁而成立的视觉隐喻。画面只服务于观点、流程或状态；可加入能强化因果和情绪的微型情境（如追踪痕迹、即将关闭的入口、被保护的目标、残留的威胁）；不加入荒诞微剧情、无关角色或装饰性桥段。

### 4. 检查与迭代

生成后按 `references/qa-checklist.md` 中对应 profile 检查。科学图解先检查因果覆盖和方向，正文插画先检查单场景可读性。出现以下问题时优先重生成或局部编辑：

- 角色不是固定细胞 IP，或颜色/道具错位
- 主角只是装饰，观点不清楚
- 只是在排列角色，没有触发、行动与结果的因果关系
- 有故事元素但与文章判断无关，或环境、配角挤占了主角动作
- 正文插画画面太满、无意中变成流程图或 PPT
- 科学图解遗漏步骤、箭头方向错误，或为了角色风格删掉必要结构
- 中文太多、错字严重或出现左上角类型标题
- 画面变成 3D、商业卡通、平面 UI 或复杂背景
- 出现无关剧情，削弱解释重点

### 5. 保存交付

在 workspace 内工作时，将最终图复制到 `assets/<article-slug>-illustrations/`，按 `01-topic-name.png` 的顺序命名。保留原始生成文件，不覆盖已有资产，除非用户明确要求替换。

## 输出口径

策略输出短而准。生成后的交付包含：生成数量、每张图用途、保存路径，以及最稳和可选的图。
